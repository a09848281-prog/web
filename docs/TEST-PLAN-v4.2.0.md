## 実機テスト

1. Android 13で監視待機を開始し、通知が維持されること。
2. Androidでコードを発行し、iPadを登録する。
3. Android側でコードを再発行し、PCを別の閲覧端末名で登録する。
4. iPadとPCで同時接続し、両方に映像と音声が流れること。
5. iPadの「切断」を押してもPCの映像と音声が継続すること。
6. PCを切断してもiPadの接続が継続すること。
7. 3台目を接続し、3台が視聴できること。4台目は上限エラーになること。
8. 片方のブラウザーだけ登録解除し、他のブラウザーは操作可能なままであること。
9. 画質・画角・FPS・ライト等の共有設定がすべての視聴端末に反映されること。
10. PTTは送信元の端末からのみ送話し、切断操作は送信元のセッションのみ閉じること。
11. 動体検知をOFF / 低 / 標準 / 高で確認し、イベント画像・CSVを確認すること。
12. 動体検知履歴の画像サムネイルをタップし、ビューアーが画面全体に表示され、閉じる・保存が動くこと。
13. ライブ映像の「静止画保存」で受信画像ビューアーが開き、画像が欠けずに表示され、閉じるとライブ再生が継続すること。
14. ビューアーの全画面ボタンをiPad Safari / PC Chromeで確認する。ブラウザーがネイティブ全画面APIに対応しない場合も、画面いっぱいのダイアログ表示を保つこと。
15. ブックマークレット経由で動体検知画像を開き、親パネルと画像表示が画面全体まで拡張し、閉じると元の位置・大きさへ戻ること。
16. ブックマークレットの画像全画面中は上部バーが隠れ、画像ビューアーの操作ボタンが使えること。
17. LocalStorage利用不可または容量不足のブラウザーでも、初期化・画像表示・接続画面が例外で停止せず、保存不可を通知すること。
18. ブラウザー通知は利用者が許可した場合のみ発生すること。
19. Safari / Chromeの背景タブや画面ロックで動体検知が停止する制約を確認すること。
20. 同一Wi-Fi / Wi-Fiとモバイル回線の両方で確認すること（TURN未構成の制限）。
21. Androidの待機中通知、カメラ・マイクのプライバシー表示、バッテリー温度・負荷を確認すること。

## 合格基準

- iPadとPCが同じAndroidから同時に映像・音声を受信する。
- 一方の切断や登録解除が他方の接続を終了させない。
- 3台上限が正しく機能する。
- 動体検知・履歴が各ブラウザー内で動き、CSV出力できる。
- 既存v4.1アプリとmain側コードに変更がない。
