# Remote Camera v4.1.0 完全統合仕様書

作成日：2026-11-18  
開発ブランチ：`rebuild-v4.1-complete-stable`  
基点：`rebuild-v4.0-ambient-audio-ptt`  
用途：個人利用  
対象：Android 13（主な検証端末 Galaxy A22 5G）／iPad Safari／PCブラウザー  
構成：GitHub Pages + Android APK + Google Apps Script + Google Sheets + WebRTC  
Firebase：不使用

## 1. 開発方針

- v3.9から蓄積したカメラ・位置情報・バックグラウンド待機・接続安定化機能を継承する。
- v4.0の環境音優先マイク、受信音量調整、音声メーター、左側大型PTTを継承する。
- v4.1は独立したプレビュー版としてビルドする。Android applicationId は `jp.a09848281.remotecamera.v41preview`。
- `main`、v3.9およびv4.0の既存ブランチを上書き・削除しない。
- デザインの色・カード構成・既存の操作方法を維持し、既存画面内に音声操作とAndroid側設定を整理して追加する。
- 登録・ログイン機能は設けず、Androidが発行する有効期限付き8桁コードによるペアリングを使用する。

## 2. システム構成

| 構成 | 役割 |
|---|---|
| Android APK | カメラ・マイク取得、Foreground Service、待機、ライト、端末情報 |
| Web / PWA | iPad・PCから接続、映像・音声表示、カメラ操作、設定 |
| WebRTC | 映像・音声・接続中の操作データを端末間で直接送受信 |
| GAS | 端末登録、ペアリング、接続シグナリング、操作命令、設定、位置情報 |
| Google Sheets | 端末・命令・シグナリング・設定・位置情報の保存 |
| GitHub Actions | JS/GAS構文検査、ソース整合性検査、Android APKビルド、APK権限検査 |

映像・音声のメディアデータは原則WebRTCで直接送信し、GASやSheetsへ録画・録音データを保存しない。STUNは使用するが、TURN中継サーバーはまだ構成していない。

## 4. Androidバックグラウンド待機

- Androidはユーザーがアプリを開き、カメラ・マイクなど必要な権限を許可した状態で「監視待機を開始」する。
- 待機中は撮影・録音を開始しない。Foreground Serviceの通知を表示し、Webからの接続要求を待つ。
- Webからの接続要求を受けた後に、カメラ・マイクを起動する。
- 待機確認間隔：省電力30秒 / 標準6秒 / 応答優先2秒
- 画面OFF中のCPU維持スイッチ（任意）。ONでは安定性を優先する一方、電池消費が増える。
- 通信量モード：Web側に従う / 超節約 / 節約 / 標準 / 高画質
- Webからカメラ・マイクの起動を許可するスイッチ
- Android設定画面を開いても、既に動作している待機サービスとWebRTC接続を停止しない。
- マイクモードは設定を保存し、接続中は既存接続を維持して次回の新規接続から反映する。

### Android OSの制約
次の状態からの即時遠隔起動は保証できない。
- Android設定からアプリを強制停止した状態
- 端末再起動後にアプリ／サービスが再始動していない状態
- カメラ・マイク権限が取り消された状態
- OSやメーカー独自の省電力機能にサービス・通信が停止された状態
- ネットワークが切断されている状態

Foreground Service、通知、Androidのプライバシー表示、ユーザーの権限を尊重する。隠れて撮影・録音する機能は設けない。

## 5. v4.1 Androidマイク設定

Androidアプリ内の「Androidマイクの集音モード」から次を選ぶ。初期値は環境音重視。

| モード | 音源・処理 | 想定用途 |
|---|---|---|
| 環境音重視 | MIC / ハードウェアAEC・NS OFF / WebRTCのエコー・ノイズ抑制OFF / 通常音声ルート | 部屋の音・小さな環境音を拾いたい場合 |
| バランス | MIC / ハードウェアNS ON・AEC OFF / 通常音声ルート | 環境音と雑音のバランス |
| 声重視 | VOICE_COMMUNICATION / ハードウェアAEC・NS ON / 通話音声ルート | 人の声を聞き取りやすくしたい場合 |

- 環境音重視は静かな音を残しやすい反面、空調音・風切り音・スピーカーの回り込み・エコーも入りやすくなる。
- Android端末のマイク位置・物理感度・メーカーのオーディオ処理はアプリから完全には制御できない。
- マイクモード変更は既存の配信を急に破棄せず、次の接続で新しいAudioDeviceModuleを作成して反映する。
- Webの音声メーターは、AndroidからWebへ届いた受信音声のレベルを表示する。Androidマイクの物理入力レベルそのものを直接測定するものではない。

## 6. v4.0から継承するWeb音声機能

- 受信音量：0〜200%。Web Audio GainNode対応環境で100%超の受信音声を増幅する。
- 200%はiPad/PC側の受信増幅であり、Androidマイクの物理入力感度を2倍にするものではない。
- Web Audio非対応時のHTML音声再生は最大100%に制限される。
- 受信音量を上げると音割れやノイズも大きくなる場合がある。
- iPad/PCからAndroidへ送るPTT音声のAndroid側再生音量を0〜100%で調整できる。Webの設定値はブラウザーへ保存し、新規接続時にも同期する。
- Android受信音声のミュート切替
- RMSベースの受信音量メーターと状態文字表示
- プッシュトーク中は半二重動作としてAndroidからの戻り音声をミュートし、ハウリングを抑える。

## 7. v4.1プッシュトークの安全性・操作性

- Web映像ビューの操作列の左側に大型ボタンを表示する。
- 押している間だけ送話する基本動作。
- 送話ロックで長押し不要の連続送話に切り替え、もう一度操作して解除できる。
- Pointer Captureを使用し、指がボタン外へ移動してもポインター終了イベントを受け取りやすくする。
- PCのSpace / Enterキーにも対応。
- 送話状態は最大3分で自動解除する安全タイマーを設ける。
- 接続終了時は送話状態・送話ロック・タイマーを解除する。

## 8. ペアリング・データ保護

- Android側に表示される有効期限付き8桁コードでWeb端末を登録する。コード有効期限は10分。
- 登録後、ブラウザーに端末専用の操作トークンを保存する。
- Android秘密情報と操作トークンを照合してAPIを制限する。
- Webのログイン・新規登録は設けない。
- 位置情報はユーザーが許可・有効化した場合だけ収集する。
- 位置情報履歴の削除機能を備える。
- 映像・音声の録画保存機能は含まない。
- 個人利用を前提とし、共有端末・不特定多数への公開をしない。

## 9. 接続・安定性の制限

- WebRTCのSTUN候補収集、自動再接続、映像フレーム監視、Androidカメラ再取得を利用する。
- TURN中継は未構成。モバイル回線とWi-Fi、異なるNAT環境などで接続が成立しない場合がある。
- GASポーリングは待機確認と初期シグナリング用。接続成立中はWebRTCデータチャネルを優先する。
- GAS実行時間制限、通信障害、スプレッドシートの一時ロックなど外部サービスの制限は無効化できない。
- 高画質・高FPSは通信量・発熱・電池消費が増える。
- ライトは端末の背面カメラ／フラッシュ対応やOSの占有状態に左右される。
