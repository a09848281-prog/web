# Remote Camera v4.2.2 — 安定性・操作性改善仕様
作成日：2026-11-19

## 目的
v4.2系を維持し、Webの左側を操作・設定、右側を映像/地図表示専用に整理する。Android監視開始時刻とアプリUID通信量をWebに表示し、映像・音声の設定をWebから即時操作できるようにする。

## Web
- 左側：ペアリング、接続/切断、画質、通信モード、画角、FPS、ライト、送話、位置情報、音声フィルター、検知設定。
- 右側：受信映像または地図のみを大きく表示。Android端末情報、監視経過時間、端末通信量、閲覧端末通信量だけをヘッダーに小さく表示。
- 16:9 / 4:3 / 1:1 / 9:16の画角をWebから変更し、接続中はWebRTC DataChannel経由でAndroidのCamera2撮影形式を変更する。失敗時は現在の映像を維持する。
- 映像全画面表示を維持。受信画像ビューアーも画面いっぱいに表示。
- FPSは15 / 20 / 24 / 30 / 60から選択。60fpsはAndroidが60fps撮影を試し、対応できない時は30 / 24 / 20 / 15fpsへフォールバック。
- Androidマイクの音声にWeb Audio APIでフィルターを適用。0%は実質未処理、100%は声を優先する強めのEQ・コンプレッサー・ソフトゲート。スライダー操作で即時反映。

## Android
- ライト切替はCameraManagerの一時的なCameraAccessExceptionを対象に最大4回まで短い待機を挟んで再試行する。成功した実状態をWebへ返し、Webは応答があるまで連続操作を無効化する。
- 監視開始時刻とUID単位のTrafficStats基準値を保存し、Webの端末情報要求に現在値を返す。
- 位置情報は直近2分以内のキャッシュがあれば先に保存・表示し、新しい測位が得られた場合に追記して更新する。新規測位の待機上限を短縮する。
- 60fps指定時は先に60fpsを試し、非対応の場合は低いFPSを試す。

## GAS
- APKのapplicationIdをv4.2とは別の `jp.a09848281.remotecamera.v422preview` にする。既存v4.2アプリと並行インストールでき、旧版のアプリデータを保持する。新アプリは別端末IDとなるため、新しいペアリングが必要。
- APIバージョンを4.2.2に更新。
- 保存可能なfpsLimitの上限を60へ拡張。
- 既存スプレッドシートのテーブル構成は変更しない。

## 通信量の表示について
AndroidのTrafficStatsはアプリUID単位の送受信量で、WebRTCだけでなくGAS待機通信なども含む概算。Android端末やOSの状態により取得できない場合がある。
Web側はWebRTCの選択中ICE経路のbytesReceived/bytesSentを優先し、取得できない環境ではRTP統計から概算する。ネットワーク層の全オーバーヘッドを完全計測する値ではない。

## 制約・注意
- 60fpsは保証ではなく上限希望値。端末性能、Camera2対応、エンコーダー、発熱、暗所、回線で低下する。
- 音声処理はAI音声分離ではない。声を完全抽出したり、環境音を完全除去したりすることは保証しない。静かな声も弱くなる可能性があるため、0%から段階的に調整する。
- GPSの速度・精度はAndroid OSの権限、屋内環境、衛星受信状態に左右される。
- ライトはAndroid端末がカメラ/フラッシュの使用を許可する時のみ切り替わる。再試行で完全保証はできない。
- STUNのみでTURNリレーは未設定。異なるネットワークやNAT環境ではWebRTC接続に失敗する場合がある。
- GitHub Actionsのビルド成功は実機試験の代わりにはならない。
- GASはGitHubの更新で自動反映されない。既存Apps ScriptにCode.gsを貼り替え、ウェブアプリを新バージョンとして再デプロイする必要がある。
