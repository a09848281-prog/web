# セットアップ手順 v3.8.0（アカウント不要・Firebase非使用）

## 1. GASとスプレッドシート
1. Google Sheetを作成します。
2. 「拡張機能」→「Apps Script」を開きます。
3. gas/Code.gs の最新版を Code.gs に貼り付けて保存します。
4. 初回セットアップの場合のみ、関数一覧から `setupDatabase()` を1回実行して権限を許可します。既存環境で `/exec` の `databaseReady:true` が確認できていれば再実行不要です。既存のシートやデータは削除しないでください。
5. v3.8の `gas/Code.gs` は既存のシート構成を維持します。既存のデータベースに対して初期化・シート削除をしないでください。
6. 初回は「新しいデプロイ」→「ウェブアプリ」。既存環境は「デプロイを管理」→編集（鉛筆）→バージョン「新バージョン」→「デプロイ」で更新します。GitHubへの更新だけではGASは自動更新されません。
7. 実行ユーザーは「自分」、アクセスできるユーザーは「全員」にします。
8. /exec URLが現在の web/config.json に設定されていることを確認します。
9. /exec URLをブラウザーで開き、JSONの `version` が `3.8.0`、`databaseReady` が `true` であることを確認します。

## 2. GitHub Pages
1. GitHubリポジトリの Settings → Pages を開きます。
2. Build and deployment の Source を GitHub Actions にします。
3. Actions → Deploy Web Pages を実行します（公開デプロイは main ブランチからのみ実行します）。
4. v3.8.0の検証用Web画面は `https://a09848281-prog.github.io/web/preview/` で公開しています。正式版のトップページ `https://a09848281-prog.github.io/web/` は変更していません。
5. v3.8プレビューを使う前に、GASのCode.gsもv3.8.0へ更新・再デプロイしてください。Web画面の起動時チェックでAPIバージョンが一致しない場合はペアリングを停止します。
6. 正式版URL： https://a09848281-prog.github.io/web/

## 3. Androidの準備
1. [最新成功ビルド #126](https://github.com/a09848281-prog/web/actions/runs/44305341304) のArtifact `remote-camera-debug-apk-v3.8` を取得してインストールします。表示名は「Remote Camera 3.8 Preview」、applicationIdは `jp.a09848281.remotecamera.v38preview` です。v3.7とは別アプリなので、**v3.7をアンインストールせず**並行インストールできます。
2. Android 13端末でアプリを開きます。
3. カメラ・マイク・通知を許可します。位置情報は任意ですが、利用する場合は「正確な位置情報」を許可し、Android本体の位置情報もONにします。待機開始後に位置情報権限を追加で許可した場合は、一度待機を停止してから再開始してください。
4. 「監視待機を開始」を押します。
5. v3.8 Previewアプリに新しい8桁のペアリングコードが表示されます。v3.7のコードとは別なので、Webの端末追加でv3.8のコードを登録してください。通知欄の「待機を停止」からバックグラウンド待機も停止できます。

## 4. iPadからペアリング
1. iPad SafariでGitHub Pagesを開きます。
2. 「Androidをペアリング」を押します。
3. Androidに表示された8桁コードを入力します。
4. ペアリングが成功すると端末が一覧に表示され、監視操作画面を使えるようになります。
5. 起動時にWeb画面がGASのPOST通信も自動確認します。「GAS接続済み」と表示されることを確認します。
6. 不要になった端末は「選択中の端末をペアリング解除」からサーバー側の操作トークンも無効化できます。

ユーザー登録・ログインはありません。操作トークンはこのiPadのブラウザーローカルストレージに保存されます。ブラウザーのサイトデータを削除した場合は、Androidアプリで「ペアリングコードを再発行」して再ペアリングしてください。

## 5. 接続テスト
1. ペアリング済み端末を選択します。
2. 「接続」を押し、iPad Safariのマイク権限を許可します。
3. 映像・音声、プッシュトゥトーク、カメラ切り替え、音量、位置情報を確認します。

## 注意
Androidの待機ポーリングは省電力30秒／標準6秒／応答優先2秒です。WebRTCの通信と操作チャネルが確立すると、接続中のGAS定期ポーリングを停止して端末間で直接通信します。STUNを使用しますがTURN中継はありません。まず同じWi-Fi/LAN内で接続を確認してください。異なるネットワーク間でも接続しやすくなりますが、ルーター・携帯回線・ネットワーク制限によっては接続できない場合があります。Androidの強制停止・再起動・権限取消・メーカー省電力制御後の自動復帰は保証されません。


## v3.7のバックグラウンド利用
- 待機はAndroidアプリを画面表示中に開き、許可を確認してから開始してください。
- 待機中はカメラ・マイクを使わず、Webからの接続要求を確認します。
- 接続中はAndroidの常時通知とシステムのプライバシー表示にカメラ・マイク使用中と表示されます。
- 画面ロック後の接続継続は、開始済みForeground Serviceが維持されている間に限り試行します。
- 強制停止・端末再起動・権限取消・メーカー省電力制御後の自動復帰は保証されません。


## v3.6から引き継いだ追加・改善
- 背面カメラからAndroidが公開している範囲で最も広い水平画角のレンズを優先します。超広角レンズがOSに公開されていない機種では画角は変わりません。
- 映像は16:9の720pを標準とし、対応しない場合は960×540、さらに640×360へ段階的に下げます。
- 接続中の通信速度・映像FPS・RTT・パケット損失率をWeb画面に表示します。
- 接続切断時は最大5回、間隔を広げながら自動再接続します。手動切断時は再接続しません。
- 全画面、表示ズーム、全体表示／画面に合わせる、接続時間、地図追尾、座標コピーを利用できます。
- 表示ズームはiPad側の映像表示を拡大する機能で、Androidカメラの光学ズームではありません。
- 位置情報は直近60秒以内のキャッシュを優先し、新しい測位が必要な場合はGPS・ネットワーク位置情報を同時に試して最大8秒待ちます。位置情報権限がなくてもカメラ待機は開始できます。


位置情報を有効にしているのに取得できない場合は、Androidの「設定 → 位置情報」をONにし、アプリの権限で「正確な位置情報」を許可してください。屋内や高層ビル周辺ではGPSの初回測位に時間がかかることがあります。


## v3.7の安定性・操作性改善（継承機能）
- 接続中に画質を変更した場合、映像送信のビットレートと最大FPSを先に反映します。Camera2の解像度／撮影FPSの再設定は次回接続時に行い、設定中の映像停止を抑えます。
- WebRTCの自動再接続では許可済みのiPadマイクストリームを再利用します。手動切断ではマイクを停止して自動再接続もしません。
- Android側は同じセッションの重複接続要求を無視し、新しいセッションに切り替わると古いPeerConnectionを整理します。
- Androidのカメラが別アプリやOSにより一時切断された場合、最大5回のカメラ再取得を試みます。別アプリがカメラを使用中は再取得できないため、そのアプリを閉じてください。
- Androidの「画面OFF中も通信を維持」をONにするとCPUをスリープさせず待機を続けやすくしますが、電池消費が増えます。通常はOFF、長時間の安定待機が必要なときだけONにしてください。
- Web画面の「接続する」「切断」を映像画面の上に配置しました。画質／通信量、位置情報、音声操作は折りたたみ式です。

## v3.7の確認項目（継承テスト）
1. 接続中に画質を720p→360p→720pと変更して、映像が停止しないか確認します（解像度の適用は次回接続）。
2. Androidのカメラを別アプリが一時使用した場合、カメラを閉じた後に自動再取得するか確認します。
3. Wi-Fiを一度OFF/ONにし、Webの自動再接続が動くか確認します。
4. Androidアプリを開き直しても、待機通知とWeb接続が継続するか確認します。
5. 「画面OFF中も通信を維持」をON/OFFして、電池消費と接続維持の差を確認します。


## v3.8の接続・操作改善
- 接続中のカメラ切替・画質変更・位置情報設定・切断は、操作用WebRTCデータチャネルが開いていればAndroidへ直接送信します。データチャネルが閉じた場合はGAS経由に切り替えます。
- iPadの「受信音量（iPad）」はAndroid本体の音量ではなく、iPadで聞くAndroid側の受信音量を調整します。
- 映像の状態表示は「映像待機中」「映像の初回フレーム待ち」「映像受信中」「映像フリーズ」などに変わります。通信がconnectedでも映像が届かなければ再接続を試みます。
- 接続が短時間disconnectedになった場合は8秒間復帰を待ちます。長く復帰しない場合はセッションを終了し、Web側から再接続します。
- GASの実行時間は6分／回の制限が残ります。制限そのものを無効化する方式ではなく、接続中のポーリング停止・シート読み取り量削減で使用量を抑えます。
- GAS処理時間はWeb画面の「GAS処理」に表示します。ここが短く、全体の応答時間が長い場合はネットワーク側の遅延が疑われます。
- GASのCode.gsはv3.8.0を貼り付けて新バージョンとして再デプロイしてください。GitHub更新だけでは既存GASデプロイは更新されません。


v3.8.0のGAS更新は [GAS再デプロイ手順](GAS-REDEPLOY-v3.8.0.md) を参照してください。v3.7とv3.8 Previewは別々のペアリング情報を使います。公開中のv3.8 Webプレビュー：https://a09848281-prog.github.io/web/preview/
