## 1. プロジェクト概要

### 1-1. 目的

Androidスマートフォンを遠隔監視カメラとして使用し、iPadの専用Webサイトからインターネット経由で映像・音声・位置情報を確認・操作できるシステムを開発する。

Androidには専用APKをインストールする。

iPadでは専用Webサイトを開き、アカウントにログインしてAndroid端末に接続する。

Androidは監視待機中に画面を消灯してロック状態にできる。

接続中は、Androidのロック画面でも映像・音声の取得を継続することを目標とする。

### 1-2. 最重要目標

1. Androidを遠隔監視カメラとして使用する。
2. Androidのロック画面でも接続中の映像・音声を取得する。
3. Androidがバックグラウンド待機中でも接続要求を受け取れるようにする。
4. Firebase、FCM、TURNを使用しない。
5. GAS・GitHub・Googleスプレッドシートを中心に構成する。
6. GASの接続先URLを利用者が入力しなくて済むようにする。
7. Androidのカメラ映像をiPadにリアルタイム表示する。
8. 音声の双方向通信に対応する。
9. 映像の画質とデータ通信量を変更できるようにする。
10. カメラの画角を可能な限り広くする。
11. Androidの位置情報を地図上に表示する。
12. 位置情報の履歴を保存・表示する。
13. 位置情報の定期取得をON/OFFできるようにする。
14. 接続中とバックグラウンド待機中で位置情報の取得間隔を別々に設定できるようにする。
15. Webサイトから新規登録・ログインできるようにする。
16. Android端末を端末IDで登録・管理できるようにする。
17. GitHubからAPKをダウンロードできるようにする。
18. 録画・録音機能を実装しない。
19. 可能な限り無料で利用できる構成にする。

## 2. 使用技術・サービス

### 2-1. 使用するサービス

| 技術・サービス | 使用目的 |
|---|---|
| Google Apps Script（GAS） | 認証、端末管理、接続要求、通信制御、履歴管理 |
| Googleスプレッドシート | アカウント情報、端末情報、設定、位置情報履歴 |
| GitHub | ソースコード管理 |
| GitHub Pages | 専用Webサイトの公開 |
| GitHub Releases | Android APKの配布 |
| WebRTC | 映像・音声のリアルタイム通信 |
| Kotlin | Androidアプリの開発 |
| Android SDK | Androidの機能利用 |
| Android Studio | APKのビルド |
| HTML・CSS・JavaScript | Web画面の作成 |

Androidアプリの開発・ビルドにはKotlin、Android SDK、Android Studioを使用する。これらは開発に必要なツールであり、追加のクラウドサービスではない。

### 2-2. 使用しないサービス

以下は使用しない。

- Firebase
- Firebase Authentication
- Firebase Realtime Database
- Firebase Cloud Messaging（FCM）
- TURNサーバー
- 有料VPS
- 有料クラウドサーバー
- 有料データベース
- 有料通信中継サービス

また、WebRTCのSTUNサーバーも使用しない。

### 2-3. 無料利用方針

GAS、Googleスプレッドシート、GitHubの無料利用範囲を基本とする。

有料契約を必要としない構成を目指す。

ただし、各サービスには利用上限があり、上限や無料提供条件は変更される可能性がある。

利用者が増えたり、アクセス回数が多くなったりした場合は、無料枠の制限に達する可能性がある。

### 2-4. 地図表示

地図表示はLeafletとOpenStreetMapを使用する。

LeafletはWeb画面の地図表示に使用するライブラリとする。

OpenStreetMapは地図データの取得先とする。

地図データの利用条件とタイルサーバーの利用規約を守る。

地図データ以外の追加バックエンドサービスは使用しない。

## 4. GAS接続設定の簡略化

### 4-1. 基本方針

利用者がGASのURLを手入力する仕組みをなくす。

GASのWebアプリURLは開発時に一度だけ設定する。

Web側はGitHub Pagesの設定ファイルに接続先を組み込む。

Android側はAPKに接続先を組み込む。

通常の利用者はURLを入力せずに使用できる。

### 4-2. Web側の設定

GitHub Pagesに接続先設定ファイルを用意する。

例：

- api-config.js
- app-config.json

Webサイト起動時に設定ファイルを読み込む。

### 4-3. Android側の設定

APKにGAS接続先を組み込む。

必要に応じてGitHub Pagesの設定ファイルから最新の接続先情報を取得できる構成にする。

### 4-4. GAS URL変更時

GASのデプロイURLを変更した場合は、設定ファイルを更新する。

Android APKに固定URLを使用している場合は、APKの更新が必要になる構成を避け、可能な限り設定ファイルから取得する。

ただし、設定ファイル自体を取得するためのGitHub PagesのURLは初回から組み込んでおく。

## 5. 通信方式

### 5-1. 基本構成

映像・音声の通信はWebRTCを使用する。

GASとGoogleスプレッドシートは接続情報の受け渡しに使用する。

WebRTCの接続が確立した後は、映像・音声を直接通信する。

### 5-2. 接続の流れ

1. Webサイトから端末を選択する。
2. WebサイトがGASへ接続要求を送る。
3. GASが接続要求を管理データに保存する。
4. AndroidアプリがGASへ接続要求の有無を確認する。
5. Androidが接続要求を受け取る。
6. Androidが接続可能な状態か確認する。
7. AndroidがWebRTCの接続処理を開始する。
8. Web側とAndroid側で接続情報を交換する。
9. WebRTCの接続を試みる。
10. 接続できた場合は映像・音声を直接送受信する。
11. 接続が終了したらカメラ・マイクを停止する。
12. Androidは待機状態へ戻る。

### 5-3. STUN・TURNを使用しない制限

STUNもTURNも使用しない。

そのためWebRTCは、利用できるネットワーク経路の範囲で直接接続を試みる。

同じWi-Fi内などでは接続できる場合がある。

異なるネットワーク間では、NATやファイアウォールの条件によって接続できない場合がある。

携帯電話回線と家庭用Wi-Fiの組み合わせなどでは接続に失敗する可能性がある。

すべてのインターネット環境で接続できる保証はしない。

接続できない場合は「直接接続できません」と表示する。

### 5-4. GASの役割

GASは以下の情報だけを扱う。

- 接続要求
- 接続状態
- WebRTCのSDP情報
- ICE候補情報
- カメラ切り替え命令
- 音量変更命令
- 画質変更命令
- 位置情報取得要求
- 設定変更命令

映像・音声そのものは扱わない。

### 5-5. Safari対応

iPad SafariでGASとの通信、WebRTC、音声再生、カメラ・マイク許可を確認する。

GitHub PagesからGASへの通信では、CORSやリダイレクトなどの制約を確認する。

通常のAPI通信でno-corsを使って応答を読めなくする方式は採用しない。

必要に応じてGAS側のHTML iframeを通信ブリッジとして利用する方式を検討する。

## 6. バックグラウンド待機・接続要求確認

### 6-1. 基本方針

Firebase・FCMを使用しないため、AndroidはGASに接続要求がないか定期的に確認する。

GASへの定期確認を完全になくすことはできない。

GAS以外の通知サービスや常時接続サーバーを使用しない条件では、外部からの接続要求をAndroidに知らせる手段が必要になるためである。

### 6-2. 待機中の確認間隔

初期設定：

- 標準：30秒間隔
- 高速確認：15秒間隔
- 低頻度：60秒間隔

標準は30秒とする。

確認間隔はWeb設定から変更できるようにする。

ただし、確認間隔を短くするとGASへのアクセス回数とAndroidの通信・電池消費が増える。

Android OSのスケジュール制御やネットワーク状態によって、指定秒数どおりに実行できない場合がある。

### 6-3. 自動接続処理

接続要求を確認した場合、Androidは以下を実行する。

1. 接続要求の認証を確認する。
2. 接続要求が有効か確認する。
3. 接続先ユーザーを確認する。
4. 必要な権限を確認する。
5. 接続処理を開始する。
6. WebRTC接続を試みる。
7. 接続結果をGASに記録する。

### 6-4. 接続要求がない場合

接続要求がない場合は、カメラ・マイクを停止したまま待機する。

次回の確認時刻まで待機する。

待機中に映像・音声通信を行わない。

### 6-5. GASへのアクセス負荷

30秒間隔で24時間確認すると、Android端末1台あたり約2,880回／日の確認リクエストが発生する。

15秒間隔では約5,760回／日となる。

端末数が増えるとGASへのアクセスも増えるため、初期状態では30秒間隔を使用する。

Google Apps Scriptには実行時間・同時実行数・各種サービスの利用上限がある。上限を超えると実行が停止する可能性があるため、実機テストで負荷を確認する。

## 7. Androidアプリ基本機能

### 7-1. 初期画面

Androidアプリ起動時に以下を表示する。

- 監視待機中
- 監視中
- 接続中
- 再接続中
- オフライン
- 端末ID
- カメラ状態
- マイク状態
- 位置情報状態
- GAS通信状態

### 7-2. 監視待機中

待機状態では以下を実行する。

- カメラ停止
- マイク停止
- GASへの接続要求確認
- 端末状態確認
- 必要な設定の保持
- 位置情報定期取得がONの場合は位置情報取得

### 7-3. 監視中

接続中は以下を実行する。

- カメラ映像の取得
- Androidマイク音声の取得
- WebRTC映像送信
- WebRTC音声送信
- Web側音声の受信
- 音量変更
- カメラ切り替え
- 画質変更
- 位置情報取得
- 通信状態監視

### 7-4. バックグラウンド動作

Androidアプリの画面を閉じても、待機サービスを維持できるようにする。

Foreground Serviceを利用する。

通知欄に動作状態を表示する。

通知には以下を表示する。

- 監視待機中
- 接続中
- 監視中
- 位置情報取得中

### 7-5. ロック画面

接続が確立している場合、ロック画面でも映像・音声の取得を継続する。

カメラ・マイク利用に必要なForeground Serviceと権限を、アプリが前面にある状態で適切に開始しておく。

Android 13のOS制限や端末メーカーの省電力機能によって、動作が停止・制限される可能性がある。

### 7-6. カメラ・マイクの起動条件

カメラ・マイクは、認証済みの接続要求を受け取り、必要な権限とOS条件を満たす場合に使用する。

待機中は原則としてカメラ・マイクを停止する。

カメラ・マイクの利用中は通知とOSのプライバシー表示で確認できるようにする。

## 8. Web新規登録・ログイン機能

### 8-1. 新規登録画面

専用Webサイトに新規登録画面を設置する。

登録項目：

- ユーザーID
- パスワード
- パスワード確認

ユーザーIDの重複を禁止する。

### 8-2. パスワード管理

パスワードを平文で保存しない。

ソルト付きの安全なパスワードハッシュ方式を利用する。

パスワード照合には一定の計算コストを設ける。

ログイン失敗が連続した場合は一時的に再試行を制限する。

### 8-3. ログイン

登録したユーザーIDとパスワードでログインできるようにする。

ログイン成功後は端末一覧画面を表示する。

ログイン状態は有効期限付きの認証トークンで管理する。

### 8-4. ログアウト

ログアウトボタンを設置する。

ログアウトすると認証トークンを無効化する。

ログアウト後は端末操作をできないようにする。

### 8-5. パスワード変更

ログイン中のユーザーはパスワードを変更できるようにする。

変更時は現在のパスワードを確認する。

## 9. Android端末登録・端末ID機能

### 9-1. 初回登録

Androidアプリを初めて起動すると、端末IDを自動発行する。

端末IDはアプリ内で管理するUUID形式とする。

端末IDを画面に表示する。

### 9-2. 登録用コード

Androidアプリに登録用ワンタイムコードを表示する。

ユーザーはWebサイトにログインし、登録用コードを入力する。

登録用コードは一定時間で失効する。

登録成功後、Android端末とWebアカウントを紐付ける。

### 9-3. 2回目以降

登録済み端末は自動的に端末一覧へ表示する。

毎回登録し直す必要はない。

### 9-4. 接続方式

Webサイトから次の2つを選べるようにする。

**端末IDで接続**

端末一覧からAndroid端末を選択する。

または端末IDを入力して接続要求を送る。

**バックグラウンド自動接続**

登録済みAndroid端末がバックグラウンド待機中の場合、GASに接続要求を登録する。

Androidが次回確認時に接続要求を受け取り、自動接続を試みる。

### 9-5. 端末管理

Webサイトから以下を操作できる。

- 端末一覧表示
- 端末名変更
- 端末ID表示
- 登録日時表示
- 最終接続日時表示
- オンライン状態表示
- 端末の登録解除

端末IDだけでは接続できないようにする。

## 10. 映像配信機能

### 10-1. 基本機能

Androidのカメラ映像をiPadのWeb画面にリアルタイム表示する。

通信方式はWebRTCとする。

映像をGoogleスプレッドシートやGASに保存しない。

### 10-2. 画質設定

Webから以下を選択できるようにする。

| 画質 | 目標解像度 | 用途 |
|---|---|---|
| 低通信量 | 360p | 通信量を最小限にする |
| 節約 | 480p | 通信量を抑える |
| 標準 | 720p | 通常利用 |
| 高画質 | 1080p | 高画質を優先 |
| 自動 | 自動調整 | 通信状況に合わせる |

実際の解像度・フレームレート・ビットレートは端末と通信環境に応じて調整する。

### 10-3. 最大画角

可能な限り広い画角で撮影する。

- 端末が利用できるカメラを確認する。
- 広角カメラがある場合は選択できるようにする。
- 不必要なデジタルズームを行わない。
- 不必要な映像クロップを避ける。
- カメラが対応する最大限の画角を利用する。

物理的なレンズ性能を超える画角は実現できない。

### 10-4. カメラ切り替え

Webから以下を選択できるようにする。

- 背面カメラ
- 前面カメラ
- 対応している場合は広角カメラ

切り替え時は新しい映像を取得し、WebRTCの映像トラックを更新する。

### 10-5. 映像表示

iPadの画面右側に映像を大きく表示する。

画面領域を最大限に使う。

映像の拡大・縮小表示にも対応する。

## 11. データ通信量モード

### 11-1. 基本方針

バッテリー系の動作モードは実装しない。

データ通信量を調整するモードは残す。

### 11-2. モード一覧

**自動**

通信状況に応じて画質・フレームレート・ビットレートを自動調整する。

**超節約**

低解像度・低フレームレートで通信量を抑える。

**節約**

480pを目安に通信量を抑える。

**標準**

720pを目安に画質と通信量のバランスを取る。

**高画質**

1080pを目安に画質を優先する。

### 11-3. 自動調整

通信状態が悪くなった場合は画質を下げる。

通信状態が改善した場合は段階的に画質を戻す。

急激な画質変更を避ける。

音声通信は映像通信より優先する。

### 11-4. Webからの変更

接続中にWeb画面からモードを変更できるようにする。

変更内容をAndroidに送信し、可能な範囲で反映する。

## 12. 音声機能

### 12-1. 通常音声

Androidのマイク音声をWebへリアルタイム送信する。

WebではiPadのスピーカーから音声を再生する。

### 12-2. プッシュトゥトーク

Web画面にプッシュトゥトークボタンを設置する。

ボタンを押している間だけWebのマイク音声をAndroidへ送信する。

ボタンを離すと送信を停止する。

### 12-3. 音声方向の自動切り替え

プッシュトゥトーク中はAndroidからWebへの通常音声を一時停止する。

プッシュトゥトーク解除後はWebからAndroidへの音声を停止する。

AndroidからWebへの通常音声を再開する。

映像は停止しない。

### 12-4. Androidスピーカー音量

WebからAndroidの音量を変更できるようにする。

音量スライダーは0～100％とする。

実際の音量はAndroid OSの音量設定の範囲内で調整する。

### 12-5. Safari音声制限

iPad Safariで音声再生を開始するには、最初にユーザー操作が必要になる場合がある。

Web側のマイクを利用する場合はマイク権限を取得する。

## 13. 位置情報機能

### 13-1. 基本方針

Androidの位置情報を取得し、Web画面の地図に表示する。

位置情報の定期取得は初期設定をOFFにする。

ユーザーがONにした場合のみ取得する。

### 13-2. 現在位置表示

地図上にAndroid端末の現在位置をマーカーで表示する。

表示情報：

- 緯度
- 経度
- 精度
- 取得日時
- 取得状態

地図の拡大・縮小・移動に対応する。

現在位置へ戻るボタンを設置する。

### 13-3. 1回だけ位置情報を取得

Webから「現在位置を取得」ボタンを押す。

Androidに取得要求を送る。

Androidは位置情報を1回取得する。

緯度・経度・精度・取得日時をWebへ返す。

定期取得がOFFの場合は、1回取得した後に終了する。

### 13-4. 定期取得

Webから定期取得をON/OFFできるようにする。

ONの場合、設定した間隔で位置情報を取得する。

設定できる間隔：

- 10秒
- 15秒
- 30秒
- 60秒
- 120秒
- 300秒
- 任意の秒数

取得間隔は秒単位で管理する。

ただし、Android OSの位置情報更新制御、GPSの状態、ネットワーク、端末メーカーの制限によって、指定秒数どおりに取得できない場合がある。

### 13-5. 接続中の位置情報設定

Webから以下を変更できるようにする。

- 位置情報取得ON/OFF
- 取得間隔
- 精度優先設定

### 13-6. バックグラウンド待機中の位置情報設定

Webから以下を変更できるようにする。

- 位置情報取得ON/OFF
- 取得間隔
- 精度優先設定

接続中とバックグラウンド待機中の設定は別々に保存する。

端末がオフラインの場合は、設定をGAS側に保存し、次回接続時にAndroidへ反映する。

### 13-7. バックグラウンド位置情報

バックグラウンド中に位置情報を取得する場合は、Androidの必要な位置情報権限を取得する。

必要に応じて位置情報Foreground Serviceを利用する。

位置情報を取得中であることをAndroid通知に表示する。

位置情報を取得できない場合は、最後に取得した位置と日時を表示する。

過去の位置を現在位置として表示しない。

### 13-8. 位置情報履歴保存

Googleスプレッドシートに以下を保存する。

- ユーザーID
- 端末ID
- 緯度
- 経度
- 精度
- 取得日時
- 取得モード

取得モードは以下とする。

- 手動取得
- 接続中
- バックグラウンド待機中

### 13-9. 履歴表示

Webから位置情報履歴を確認できるようにする。

機能：

- 履歴一覧
- 日時による絞り込み
- 地図上への履歴表示
- 地点を結ぶ移動経路表示
- 地点を選択して日時を確認
- 地図上の現在位置表示
- 過去の位置への移動

### 13-10. 履歴削除

Webから以下の削除を行えるようにする。

- 選択した1件
- 指定期間の履歴
- 全履歴

削除前に確認画面を表示する。

削除した履歴は復元できない仕様とする。

### 13-11. 履歴保存時の通信切断

位置情報を取得した時に通信が切断されていた場合は、Android端末内に一時保存する。

通信が回復した後、GASへ送信する。

一時保存する位置情報の件数や期間には上限を設ける。

## 18. セキュリティ仕様

### 18-1. 通信

WebサイトはHTTPSで公開する。

GASとの通信もHTTPSを使用する。

WebRTCのメディア通信は暗号化された通信を使用する。

### 18-2. 認証

ログイン済みユーザーだけが端末を操作できるようにする。

端末IDだけで接続できないようにする。

端末とユーザーの所有関係を接続要求ごとに確認する。

### 18-3. パスワード

パスワードを平文で保存しない。

ソルト付きの安全なハッシュ方式を使用する。

ログイン失敗時の制限を設ける。

### 18-4. 認証トークン

認証トークンには有効期限を設定する。

ログアウト時にトークンを無効化する。

トークンが漏えいした場合に再発行・無効化できるようにする。

### 18-5. 端末登録

登録用コードは一定時間で失効させる。

一度使用した登録用コードは再利用できないようにする。

他人の端末を勝手に登録できないようにする。

### 18-6. GAS・スプレッドシートの保護

スプレッドシートを一般公開しない。

データへのアクセスはGAS経由に限定する。

GASの各処理で認証と所有者確認を行う。

同時書き込みによるデータ破損を防ぐため、必要な箇所でLockServiceを使用する。

## 24. 重要な制約・未保証事項

### 24-1. GASへの定期アクセス

Firebase・FCMを使わないため、AndroidからGASへ定期的に接続要求を確認する必要がある。

GASへの定期アクセスを完全にゼロにしたまま、遠隔からAndroidへ接続要求を即時通知することは、本仕様のサービス構成では実現できない。

### 24-2. 接続速度

接続要求を確認するまでの待ち時間は、設定した確認間隔とネットワーク状態に依存する。

30秒間隔の場合、接続要求の確認まで最大で約30秒程度かかる可能性がある。さらにWebRTCの接続処理時間が必要になる。

### 24-3. TURN・STUNなし

STUN・TURNを使わないため、異なるネットワーク間の接続成功率は保証できない。

特にNATやファイアウォールが厳しい環境では接続できない場合がある。

### 24-4. Androidバックグラウンド制限

Android OSがサービスの実行を制限した場合、接続要求の確認や自動接続が遅れたり失敗したりする可能性がある。

カメラ・マイクのバックグラウンド利用にはOSが定める権限とForeground Serviceの条件を守る必要がある。

### 24-5. 無料枠

GAS、GitHub、Googleスプレッドシートの無料利用範囲には上限がある。

利用人数・位置情報取得回数・GASアクセス回数が増えると制限に達する可能性がある。

無料であることや、将来にわたる無料提供を保証するものではない。

## 25. 最終仕様まとめ

本システムは、Android 13スマートフォンを遠隔監視カメラとして使用し、iPad第9世代のSafariから操作する。

利用者は専用Webサイトから新規登録・ログインし、Android端末を端末IDで登録する。

WebサイトはGitHub Pagesで公開する。

Androidの端末管理、認証、接続要求、設定、位置情報履歴はGASとGoogleスプレッドシートで管理する。

GASの接続先URLは開発時に組み込み、利用者が入力しなくて済むようにする。

Firebase・FCM・TURN・STUN・有料サーバーは使用しない。

Androidは待機中にGASへ定期確認を行い、接続要求を受信したらWebRTC接続を試みる。

接続確立後は映像・音声をWebRTCで直接通信する。

映像画質・通信量モード・カメラ・音声・音量をWebから操作できるようにする。

Androidの位置情報は地図上に表示し、履歴を保存・表示・削除できるようにする。

位置情報の定期取得はON/OFFでき、接続中とバックグラウンド待機中で別々の取得間隔を設定できるようにする。

録画・録音機能は実装しない。

APKはGitHub Releasesからダウンロードできるようにする。

以上を本システムの開発仕様とする。
